# Waterfall / Cascada

## ¿Qué es?

Waterfall, o modelo en cascada, es una metodología lineal y secuencial para manejar proyectos de software. Esto significa que el proyecto avanza por etapas fijas y ordenadas. Primero se levantan los requisitos, después se diseña el sistema, luego se programa, se prueba y finalmente se entrega.

En esta metodología no se pasa a la siguiente etapa hasta terminar la anterior. Por eso se le llama “cascada”, porque el avance baja de una fase a otra de forma ordenada.

## ¿Para qué sirve?

Sirve para proyectos donde los requisitos están bien definidos desde el inicio y no se espera que cambien mucho durante el desarrollo.

Es útil cuando el cliente ya sabe exactamente qué necesita y el equipo puede planear todo antes de comenzar a programar.

También sirve para proyectos donde se necesita mucha documentación, control formal y aprobación por etapas.

## ¿Cómo se aplica?

Se aplica siguiendo fases ordenadas:

1. Recolección de requisitos.
2. Análisis del sistema.
3. Diseño de arquitectura.
4. Programación.
5. Pruebas.
6. Implementación.
7. Mantenimiento.

Cada fase debe revisarse y aprobarse antes de continuar con la siguiente. Esto ayuda a tener control del proyecto, pero puede ser poco flexible si el cliente cambia de opinión a la mitad del desarrollo.

## Ejemplo

Una empresa necesita un sistema de nómina interno. Las reglas ya están definidas: cálculo de sueldo, descuentos, impuestos, bonos, horas extra y reportes administrativos.

Como los requisitos son claros, el equipo primero documenta todo lo que debe hacer el sistema. Después diseña la base de datos, crea las pantallas, programa las funciones, realiza pruebas y finalmente entrega el sistema.

Este proyecto puede manejarse con Waterfall porque no necesita cambios constantes y requiere mucho control en cada fase.
