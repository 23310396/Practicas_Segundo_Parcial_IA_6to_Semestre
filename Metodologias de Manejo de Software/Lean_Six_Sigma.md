# Lean Six Sigma / Black Belt

## ¿Qué es?

Lean Six Sigma es un enfoque de mejora de procesos que combina dos ideas principales.

Lean busca eliminar desperdicios, es decir, actividades que no aportan valor al proyecto. Por ejemplo, esperas innecesarias, retrabajo, tareas duplicadas o procesos lentos.

Six Sigma busca reducir errores, defectos y variaciones en los procesos.

En este tema, Black Belt no es una metodología separada. Black Belt es un rol o nivel de especialización dentro de Six Sigma. Una persona Black Belt normalmente lidera proyectos de mejora y analiza problemas complejos de calidad.

## ¿Para qué sirve?

Sirve para mejorar la calidad del proceso de desarrollo de software.

Se utiliza cuando un equipo ya trabaja con un proceso definido, pero tiene problemas como:

- Muchos errores después de publicar una versión.
- Retrabajo constante.
- Retrasos en entregas.
- Procesos lentos.
- Mala comunicación entre áreas.
- Fallas repetitivas en pruebas.

En software, Lean Six Sigma ayuda a reducir defectos, mejorar tiempos de entrega y controlar mejor la calidad.

## ¿Cómo se aplica?

Normalmente se aplica usando el ciclo DMAIC:

| Fase | Significado | Aplicación en software |
|---|---|---|
| Define | Definir | Identificar el problema del proceso |
| Measure | Medir | Medir errores, tiempos o fallas |
| Analyze | Analizar | Buscar causas raíz |
| Improve | Mejorar | Aplicar soluciones |
| Control | Controlar | Mantener la mejora |

Descripción del ciclo:

1. Define:
Se define el problema. Por ejemplo, demasiados errores después de cada actualización.

2. Measure:
Se mide el problema. Por ejemplo, cantidad de bugs por versión o tiempo promedio de corrección.

3. Analyze:
Se analizan las causas. Por ejemplo, falta de pruebas automatizadas o mala revisión de código.

4. Improve:
Se aplican mejoras. Por ejemplo, crear pruebas unitarias, revisar código antes de subirlo y usar checklist.

5. Control:
Se controla el proceso para que la mejora se mantenga. Por ejemplo, revisar cada versión con métricas de calidad.

## Ejemplo

Una empresa tiene una plataforma web que presenta muchos errores cada vez que se publica una nueva versión.

Primero, el equipo define el problema: las actualizaciones generan demasiados bugs.

Después mide cuántos errores aparecen por versión y cuánto tiempo tarda el equipo en corregirlos.

Luego analiza las causas y descubre que no hay suficientes pruebas automatizadas, además de que algunos cambios se suben sin revisión de código.

Como mejora, el equipo implementa pruebas unitarias, revisión obligatoria por otro desarrollador y una lista de verificación antes de publicar.

Finalmente, controla el proceso midiendo si los errores disminuyen en las siguientes versiones.

Lean Six Sigma funciona bien en este caso porque ayuda a mejorar la calidad del proceso y reducir fallas repetitivas.
