# Scrum

## ¿Qué es?

Scrum es un marco de trabajo basado en Agile que se utiliza para organizar equipos de desarrollo de software. Divide el trabajo en ciclos cortos llamados sprints, que normalmente duran de 1 a 4 semanas.

En cada sprint se planea, se desarrolla, se prueba y se entrega una parte funcional del producto.

Scrum no es exactamente una metodología completa, sino un marco de trabajo que ayuda a aplicar principios ágiles de manera organizada.

## ¿Para qué sirve?

Sirve para equipos de software que necesitan organizar tareas, entregar avances constantes y adaptarse a cambios del cliente.

Es útil en proyectos medianos o grandes donde hay varias funcionalidades, varios integrantes y necesidad de comunicación frecuente.

También ayuda a que el equipo tenga claridad sobre qué se está haciendo, quién lo está haciendo y qué se entregará al final de cada sprint.

## ¿Cómo se aplica?

Scrum se aplica con roles, eventos y artefactos.

Roles principales:

1. Product Owner:
Define las prioridades del producto y representa las necesidades del cliente.

2. Scrum Master:
Ayuda a que el equipo siga Scrum y elimina obstáculos.

3. Developers:
Son quienes diseñan, programan, prueban y entregan el software.

Eventos principales:

1. Sprint Planning:
Se decide qué tareas se harán durante el sprint.

2. Daily Scrum:
Reunión corta diaria para revisar avances, problemas y pendientes.

3. Sprint Review:
Se presenta el avance terminado al cliente o interesados.

4. Sprint Retrospective:
El equipo analiza qué puede mejorar para el siguiente sprint.

Artefactos principales:

1. Product Backlog:
Lista general de requisitos y funcionalidades.

2. Sprint Backlog:
Lista de tareas seleccionadas para el sprint actual.

3. Incremento:
Parte funcional del software entregada al final del sprint.

## Ejemplo

Un equipo desarrolla un sistema escolar. En el Product Backlog se colocan funciones como inicio de sesión, registro de alumnos, captura de calificaciones, reportes PDF y control de asistencia.
En el primer sprint se desarrolla el inicio de sesión. En el segundo sprint se crea el registro de alumnos. En el tercero se agregan calificaciones. En el cuarto se generan reportes.
Al final de cada sprint, el equipo muestra el avance al cliente. Si el cliente pide cambiar la forma de capturar calificaciones, esa mejora se agrega al backlog y se planea para un sprint posterior.
Scrum funciona bien en este caso porque permite avanzar por partes y revisar continuamente el producto.
